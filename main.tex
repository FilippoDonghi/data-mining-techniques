\section{Introduction}
\label{sec:intro}

This report describes our solution for Assignment 2 of Data Mining Techniques. The task is to rank hotel properties per search query (\texttt{srch\_id}) so that booked hotels appear at the top, followed by clicked hotels, measured with NDCG@5 on the Kaggle competition server.

The data contains approximately five million rows for training and five million for testing. Each row is one displayed property for one search query, with rich contextual, property, and competitor information. We followed a CRISP-DM style workflow: (i) related work and business framing, (ii) exploratory analysis, (iii) feature engineering and split strategy, (iv) modeling and evaluation with at least two methods, and (v) deployment considerations including ethical AI bias analysis and mitigation.

Our best local model is a gradient boosting rank surrogate with fairness reweighting in training. It improves strongly over a recommender-style popularity baseline while reducing performance disparity between family and non-family queries.

\section{Related Work and Business Understanding}
\label{sec:related}

The business objective is to improve ranking quality in hotel search, because better ranking increases user satisfaction and conversion (clicks/bookings). This is a recommender systems problem with context-aware ranking constraints.

Prior recommender literature highlights three relevant ideas. First, collaborative and latent-factor methods are effective at capturing user-item preference patterns \cite{koren2009matrix}. Second, pairwise and listwise ranking methods (e.g., LambdaMART) are highly suitable when the evaluation target is NDCG \cite{burges2010ranknet}. Third, implicit-feedback recommenders (click/view/book interactions) require careful weighting of signal strength \cite{rendle2009bpr}.

Work from the original Expedia personalized hotel search challenge also emphasizes the value of hotel characteristics, location attractiveness, user purchase history, and competitor information, and reports combining multiple ranking models for the final hotel ordering \cite{liu2013expedia}. This motivated our two-model setup:
\begin{itemize}
\item A recommender-style popularity model with Bayesian smoothing (strong interpretable baseline).
\item A feature-rich gradient boosting model as our final method.
\end{itemize}

\section{Data Preparation}
\label{sec:prep}

\subsection{Target Construction}
Following the competition definition, we used graded relevance:
\[
\text{relevance} = 5 \cdot \texttt{booking\_bool} + 1 \cdot (\texttt{click\_bool} \land \neg \texttt{booking\_bool}).
\]
This keeps booked items as the highest-signal outcomes while still rewarding clicks.

\subsection{Train/Validation Strategy}
To avoid leakage, we split by \texttt{srch\_id} (query-level split), not by row. This prevents rows from the same search appearing in both train and validation.

\subsection{Feature Engineering}
We engineered four groups of features:
\begin{itemize}
\item \textbf{Raw context/property features:} site, destination, stars, review score, price, promotion, booking window, party size, etc.
\item \textbf{Competitor aggregates:} mean \texttt{comp\_rate}, mean \texttt{comp\_inv}, and mean \texttt{comp\_rate\_percent\_diff} over competitors 1--8.
\item \textbf{Within-query relative features:} price rank percentile, price minus search mean, stars minus search mean, review minus search mean.
\item \textbf{Historical popularity priors:} global property score and destination-level score with Bayesian smoothing.
\end{itemize}

For missing values, we used model-compatible handling (tree model with native missing support) and aggregate smoothing/fallbacks where required.

\section{Modeling and Evaluation}
\label{sec:model}

\subsection{Metric}
We evaluated with NDCG@5 per query and averaged over queries, matching the competition objective.

\subsection{Technique 1: Recommender-Style Popularity Baseline}
As a recommender systems technique, we ranked hotels using historical relevance priors with Bayesian smoothing:
\begin{itemize}
\item Global property popularity: relevance per \texttt{prop\_id}.
\item Destination-conditional popularity: relevance per \texttt{srch\_destination\_id} and \texttt{prop\_id} together.
\item Final score: weighted combination (0.4 global + 0.6 destination-specific).
\end{itemize}

This baseline is simple, scalable, and interpretable, and it captures collaborative signal from aggregate user interactions.

\subsection{Technique 2: Gradient Boosting Rank Surrogate}
Our main model is a pointwise \texttt{HistGradientBoostingRegressor} trained on graded relevance labels. Key parameters:
\begin{itemize}
\item \texttt{max\_depth=8}
\item \texttt{learning\_rate=0.06}
\item \texttt{max\_iter=300}
\item \texttt{l2\_regularization=0.02}
\end{itemize}

Although pointwise, this model works well because features include query-relative comparisons and strong priors.

\subsection{What Did Not Work Well}
Two observations from our iteration cycle:
\begin{itemize}
\item Using only absolute features (without within-query relative features) reduced top-rank quality.
\item A pure global popularity ranking over-favored historically strong properties and underfit query context.
\end{itemize}

\section{Deployment and Ethical AI}
\label{sec:deploy}

\subsection{Scalable Deployment Discussion}
A production deployment can be implemented as a two-stage architecture:
\begin{itemize}
\item \textbf{Offline batch layer:} refresh popularity priors and retrain gradient boosting model daily/weekly.
\item \textbf{Online ranking layer:} compute lightweight query-relative features in real time, score candidate hotels, and return top-$k$ list.
\item \textbf{Monitoring:} track NDCG proxies, CTR/booking rates, latency, drift, and fairness gaps over time.
\end{itemize}

The feature design in this report is compatible with this architecture: heavy aggregates are precomputed offline, while per-query transforms are low-latency.

\subsection{Bias Detection}
We audited group fairness across two user-query segments:
\begin{itemize}
\item \textbf{Family queries:} \texttt{srch\_children\_count > 0}
\item \textbf{Non-family queries:} \texttt{srch\_children\_count = 0}
\end{itemize}

Using NDCG@5 by group as the fairness metric:
\begin{itemize}
\item Before mitigation: family 0.2997, non-family 0.2754, gap 0.0243.
\end{itemize}

\subsection{Bias Mitigation and Effectiveness}
We applied a \textbf{pre-processing reweighting} technique: during model training, rows from family queries received weight 1.6 while others kept weight 1.0.

After mitigation:
\begin{itemize}
\item Family NDCG@5: 0.2962
\item Non-family NDCG@5: 0.2761
\item Gap: 0.0201
\end{itemize}

This reduced the group performance gap by about 17\% with only a very small global NDCG@5 decrease (0.2813 to 0.2810), which we consider a reasonable trade-off.

\section{Final Model and Submission}
\label{sec:final}

Our final submission model is the bias-mitigated gradient boosting rank surrogate trained with the engineered feature set and popularity priors. The generated submission file follows Kaggle format with columns \texttt{srch\_id, prop\_id} sorted by descending predicted relevance within each query.

\section{What We Learned}
\label{sec:learned}

This assignment improved our understanding in three ways:
\begin{itemize}
\item \textbf{Ranking mindset:} optimizing query-level top-$k$ quality is different from standard classification.
\item \textbf{Feature engineering impact:} relative within-query signals were more valuable than many raw features.
\item \textbf{Responsible modeling:} fairness auditing and mitigation can be integrated with small performance cost.
\end{itemize}

Main challenges were data scale, missingness, and balancing relevance optimization with fairness. Unexpectedly, a simple popularity recommender already gave a strong baseline, showing the value of historical interaction priors in travel recommendation.

\section{Conclusion}
\label{sec:conclusion}

We developed and evaluated two ranking approaches for hotel recommendation, including a recommender-style popularity baseline and a gradient boosting model with engineered contextual features. The final model achieved the best local NDCG@5 while also reducing group disparity through pre-processing reweighting. The resulting pipeline is reproducible, scalable to production-style ranking, and aligned with both performance and ethical AI requirements of the assignment.
